# Raksha — Secret Wards privacy firewall (Yugaantar DevForge, Track 3)

Raksha turns a folder of messy Indian hospital exports (CSV/TSV in any encoding, nested JSON, FHIR R4
bundles, free-text notes in English, Devanagari Hindi and Hinglish) into a research-safe release:
direct identifiers removed, the same patient linked across files and hospitals under one keyed
pseudonym (`PSN-XXXXXX`), quasi-identifiers generalised, and all clinical content kept.

**Team BreakThrough.** The 2-page Project Brief PDF is [`docs/brief.pdf`](docs/brief.pdf).

## What makes it different (USP)

0. **Stigma Shield: extra protection for the patients a leak would hurt most.** A record that mentions
   HIV, TB, mental illness or a suicide attempt, MTP/abortion, sexual assault/POCSO, leprosy, substance use
   or sex determination (English, Devanagari or Hinglish: `PLHIV`, `ICTC`, `मानसिक रोग`, `garbhpaat`,
   `nasha mukti`, ...) marks its patient. Indian law singles these out (HIV/AIDS Act 2017, Mental
   Healthcare Act 2017, MTP Act, POCSO, PCPNDT). For those patients only: wider age bands, state-only
   location when the district would leave them in a class below k, the name of the condition-revealing
   facility removed (`ART Centre, [FACILITY]`) while the diagnosis, codes and values stay, stricter name
   detection, and a **honey-PII self-check**: every identifier found in their notes is swapped in memory
   for an invented one of the same shape (checksum-valid fake Aadhaar, same-format phone, synthesised
   name at least as name-like as the original), the note is sanitised again, and if any planted value
   survives the note is re-sanitised in the strictest mode (or quarantined if a planted number or most
   planted names still survive). Only counts reach `report.json` (`stigma_shield`). 30-second demo:
   `bash dev_eval/demo_stigma.sh`.
1. **Three scripts, one person.** Names are matched across English, Devanagari and Hinglish through
   schwa-aware transliteration, a phonetic fold and a consonant skeleton, so `थिवरेश` in a Hindi note
   and `Thivaresh` in a CSV link to the same pseudonym.
2. **Context beats lists.** The meaning traps are handled by rules, not by a bigger dictionary:
   `C/O fever` vs `C/O <name>`, `H/O TB`, ASHA worker vs a person, doctors kept, eponyms
   (`Babinski sign`) and doses shielded. Unseen names are found from Hinglish/Hindi grammar plus a tiny
   synthetic-trained name scorer, and the practice set still leaks 0 values with the gazetteer emptied.
3. **Linkage that would rather abstain than merge.** A name alone never links; hard vetoes
   (conflicting IDs/DOB/sex/age/relative) block merges, and clusters merge only when no cross pair is
   vetoed (practice set: precision 1.00, recall 1.00, 0 wrong merges).
4. **Patient-level privacy.** One keyed date shift and one age band per patient (intervals such as a
   9-day stay stay exact), a k-anonymity planner over the quasi-identifiers that are actually
   released, rare-diagnosis escalation to the coarsest level, with measured attacker numbers in `report.json`.
5. **Assume breach.** Stdlib only, offline, deterministic, in-memory, PII-free logs and errors,
   secret read once from `RAKSHA_SECRET` and dropped from the environment, broken files quarantined.

* **Models: one small classifier, nothing else.** `raksha/namefind_weights.json` (114 KB) is a
  character n-gram **logistic regression with 6,934 parameters** (6,933 feature weights + 1 bias) that
  scores whether a single word looks like an Indian personal name. It is trained **only on synthetic
  tokens** generated by `scripts/train_namefind.py` from generic morphology (name onsets/endings and random
  Indic consonant-vowel syllables vs drug INN stems, clinical roots, place roots, English and Hinglish common
  words, and the shipped Hindi vocabulary transliterated); no kit/dev data, names or
  answers are used. Training is stdlib-only and deterministic (seeded, byte-identical weights on re-run;
  synthetic hold-out P 0.96 / R 0.98). No LLMs, no generative models, no pretrained transformers, no
  spaCy/NER models. Everything else is rules, small hand-written gazetteers, transliteration,
  phonetic/fuzzy matching and deterministic algorithms. Nothing is downloaded at run time; no network calls.
* **Provenance of the word and name lists.** Every list is hand-written general knowledge, public
  administrative data or generic morphology; none is extracted from the kit, the practice set, its
  answer key or `acceptance.py`, and the test suites use invented names only.
  `raksha/data/first_names.txt` and `surnames.txt`: common Indian given names and census-level family
  names, typed by hand as a general gazetteer (the pipeline also works without them; see the
  no-gazetteer run). `places.txt`: public lists of the 75 Uttar Pradesh districts, Indian states and
  large cities, used only as a guard so a place is never read as a person. `drugs.txt`,
  `medical_terms.txt`: common generic/brand drug names and clinical vocabulary (keep-lists, never
  redacted as names). `stop_latin.txt`, `stop_hindi.txt`, `common_words.txt`, `honorifics.txt`,
  `honorific_suffixes.txt`: English/Hinglish/Hindi function words, admin words, titles and kinship
  terms. `stigma_terms.txt`: public clinical and national-programme vocabulary for stigmatised
  conditions (NACO/NTEP/NLEP/mental-health/MTP/POCSO/PCPNDT terms in three scripts). In `raksha/namefind.py`: generic stoplists, pan-Indian surnames and short name onsets/endings
  (morphology, not whole given names). The classifier weights come from synthetic tokens only (above).
* Python 3.10+ standard library only: **no third-party packages at all**, so the output is
  byte-identical whether or not anything is pip-installed (verified on 3.10 and 3.13, with and without
  PyYAML/RapidFuzz/charset-normalizer present). CPU only, offline, deterministic. Practice set (200 files):
  about 1.9 s and 35 MB peak RSS. A synthetic 2,400-file / 6,400-record set runs in about 12 s and 225 MB.

## Setup and quick start

Requirements: Python 3.10 or newer, nothing else (no GPU, no network, no packages).

```bash
git clone <repo> && cd <repo>
python3 --version                        # 3.10+
pip install -r requirements.txt          # a no-op: the file lists no packages (stdlib only)
export RAKSHA_SECRET='…'                 # required; never written anywhere
python3 main.py --input /path/to/input --output /path/to/out
python3 dev_eval/validate_output.py --input /path/to/input --output /path/to/out   # -> CONTRACT OK
```

Checks and tests (all offline):

```bash
python3 tests/test_guardrails.py         # forbidden packages, network imports, randomness, HKDF vector
python3 tests/test_namefind.py           # unseen-name finder (invented names) and over-redaction guards
python3 tests/acceptance_extended.py     # end-to-end traps, linkage, determinism, secret handling
python3 tests/test_probes.py             # leak probes from reviews, output-folder safety, symlinks, report counts, hash seed
python3 tests/test_isolation.py          # pipeline never imports dev_eval/ nor opens answer-key / attacker files
python3 tests/test_stigma.py             # Stigma Shield: trilingual detector, honey values, planner, self-check counts
python3 tests/test_improve.py            # self-improvement loop building blocks
python3 tests/test_hardclasses.py        # adversarial leak classes: spelled ages, holidays, wrapped phones, PAN, aliases
python3 tests/test_structural.py         # v1.9: hidden characters, odd phones, deep FHIR, names in keys/headers/file names, bad files
python3 tests/test_gemini_cases.py       # v1.9: the Gemini cases checker and the --gemini-cases loop
bash dev_eval/demo_stigma.sh             # 30-second before/after demo of the Stigma Shield (invented notes)
bash tests/test_offline.sh               # pipeline under a no-network namespace
python3 scripts/train_namefind.py        # optional: rebuilds raksha/namefind_weights.json byte-identically
```

If `RAKSHA_SECRET` is missing the program exits with code 2, prints a fixed message and writes
nothing. The secret is removed from the process environment right after it is read.

Container run as the organisers do it (install in a build stage, run with no network):

```bash
docker run --rm --network none --cpus=2 --memory=4g -e RAKSHA_SECRET=practice \
  -v "$PWD":/app -v /data/in:/in:ro -v /data/out:/out -w /app python:3.11-slim \
  python main.py --input /in --output /out
```

## Architecture

```
 input/ ──► Pass 0  LOAD      walk (sorted) ─ decode ─ sniff ─ parse ─► broken/binary/empty ⇒ QUARANTINE
              │
              ▼
           Pass 1  HARVEST   names from structured name columns of THIS input only ─► runtime lexicon
              │              per-source date-order votes (DD/MM vs MM/DD), safe filename tokens
              ▼
           Pass 2  EXTRACT   each record (CSV row / JSON record / FHIR Patient / text doc) ─► Unit:
              │              profile (names, relatives, IDs, phones, DOB, birth year, sex, village, PIN),
              │              QIs (age, district, diagnosis, length of stay), dates
              ▼
           Pass 3  LINK      blocking (IDs, phone, name skeletons, relative) ─► rule scoring with vetoes
              │              ─► veto-aware clustering ─► HMAC pseudonym per cluster
              ▼
           Pass 4  PLAN      per-patient keyed date shift; k-anonymity levels; rare diagnosis escalation
              │              ─► suppression; risk metrics
              ▼
           Pass 5  REWRITE   format-preserving rewrite ─► residual exact-value sweep ─► re-parse check
              ▼
 output/ ◄─ sanitized/…  records.jsonl  report.json
```

### Detection (Indian PII, three scripts)

* **Clinical shields first.** Doses (`650 mg`), frequencies (`1-0-1`), `x 5 days`, BP/pulse/labs,
  ICD codes, organisation names (`… Hospital`, `… Sadan`), UUIDs and eponyms (`Babinski sign`,
  `Koch's`) are protected spans that no PII rule may overwrite. Doctors (`Dr.`, `डॉ.`) are kept.
* **Identifiers.** Aadhaar (spaced, masked `XXXX XXXX 1234`, Verhoeff used as a booster), ABHA
  number/address, PAN, phones (+91, 0-prefixed, split `98765 43210`, landlines, Devanagari digits),
  emails, labelled IDs (UHID/MRN/IPD/Reg/policy/PM-JAY), glued record IDs (`XYZ-IPD-01234`), PIN with context.
* **Names.** Context first, lists second: label:value pairs (`Naam:`, `मरीज़ का नाम:`, `Patient Name:`),
  relation markers with trap handling (`S/o`, `W/o`, `D/o`; `C/O fever` vs `C/O Thivaresh`; `H/O TB` vs
  `H/O Thivaresh`; `X की पत्नी Y`), relation nouns, Hinglish postpositions (`Gonavati ka BP`), honorifics and
  kinship suffixes (`ji`, `bhaiya`, `behenji`), role cues (`witnessed by`, `X Y (attendant)`,
  `X Y, mob 98…`), the subject of a relation marker (`Gonavati, W/o Kelvansh`), and the record's own
  patient name inside its free text. Gazetteers and the runtime lexicon (names learned from the
  structured columns of the current input) catch the rest; ambiguous words (`Asha` = ASHA worker)
  need person context. With the built-in gazetteer emptied, the practice set still leaks 0 of 3,230 values.
* **Unseen given names.** A family name or gendered suffix (`Devi`, `Kumari`, `Bano`, `Begum`, `Yadav`, …)
  pulls in up to two preceding Titlecase words that are not stop/common/medical/place words
  (`Gonavati Devi`). Hinglish argument markers (`X ne/ko/se/aur …`), kin/role nouns with a copula
  (`the attendant was X`, `neighbour: X`) and `X ki maa Y` are cues too. A **second pass** adds every
  token of a name found in a cued context to the runtime lexicon before rewriting, so the same word is
  also removed where it later stands alone (`Thivaresh aur uski wife …` … `Thivaresh was advised …`).
* **Unseen-name finder** (`namefind.py`). Every word is scored by the n-gram classifier plus Indic
  name suffixes; a span is a name when score + context passes a threshold. Context cues are right-hand
  Hinglish/Hindi grammar (`ne`/`ने`, `ko`/`को`, `ka/ki/ke`, kin/honorific nouns, `kal/aaj … discharge`)
  and English subject verbs, so cue-less lower-case Hinglish (`aaj thivaresh ne khana khaya`) and
  Devanagari (`थिवरेश ने दवा ली`) are covered. Found names are then propagated to their other
  occurrences in the same document (cross-script key). Guards against over-redaction: stop / common /
  medical / place words (Devanagari words are also checked through their transliteration), an unknown
  word after a weak Hinglish cue must have classifier probability >= 0.3, and a weakly-detected word is
  dropped in complaint/drug/place frames (`X ki shikayat`, `ko X hai`, `Tab X`, `Started X`,
  `X se aaye`, `X ko refer`, `X में रहते`).
* **Cue-less frames.** The first word of a clause whose predicate is a person verb (honorific `aaye`,
  `gaye`, `chale`, `bharti`, `bataya`, `bole`; `आए`, `गए`, `भर्ती`, `बताया`, `बोले`), an honorific state
  (`ab theek hain`), an English object of `spoke to / informed / told / called`, or a subject of
  `was admitted/discharged` is a name if it is an unknown, name-shaped word (scorer >= 0.3, not a
  stop/common/medical/place/role word, not a Devanagari spelling of an English word). Singular symptom
  verbs (`bukhar aaya`, `हिचकी आई`) and plural nouns (`झटके आए`) are excluded by design.
* **Hidden places.** File names and parent folders, JSON keys, CSV headers, export metadata paths,
  FHIR extensions (`…/mothers-name`), base64 attachments and base64 strings inside JSON are all scanned.

### Linkage

Profiles compare names via transliteration fold + consonant skeleton + Jaro-Winkler with IDF weights.
Following the truth rule, a pair is linkable only with (1) a shared strong identifier (Aadhaar, ABHA,
PAN, UHID/MRN, insurance), (2) a shared phone with a compatible given name and age, or (3) a matching
name plus a second clue (DOB, relative, or village with birth years within 1). A name alone never links.
Hard vetoes: conflicting strong IDs or DOBs, sex conflict, birth years more than 3 apart, incompatible
names (given- or family-name disagreement), same father/spouse relation with a different name. Clusters
merge only if no cross pair is vetoed; weak fragments attach only when exactly one cluster fits.

### Pseudonyms, dates and the secret

Sub-keys come from `RAKSHA_SECRET` with HKDF (stdlib, RFC 5869: extract = HMAC(salt, secret), then
expand; a unit test checks the RFC test vector) under separate labels for pseudonyms, date shifts and
file tokens. No randomness is used anywhere (a test forbids `os.urandom`, `random`, `secrets`, `uuid4`). A pseudonym is `PSN-` + 6 Crockford base-32 characters of an HMAC over the
cluster anchor (the sorted input coordinates of its members), so it is stable for the same input and
secret, changes completely with a different secret, and cannot be inverted from patient data. Each
patient (or each unlinked record) gets its own keyed shift in ±[14,180] days, so intervals such as a
9-day stay are exact and there is no global offset to recover.

### Privacy layer — config/policy.yaml

```yaml
date_shift:   {min_days: -180, max_days: 180, min_abs_days: 14}
age:          {band_widths: [10, 20], suppressed_band_width: 40, topcode: 90}   # bands always contain the true age
location:     {keep_pin3_at_level: -1, keep_district_up_to_level: 1, village_to: district}
k_anonymity:  {k: 5, max_level: 1, rare_diagnosis_min_level: 1, rare_diagnosis_suppress: unique_with_facts,
               suppress_below_k: false}
linkage:      {age_veto_years: 3, phone_degree_cap: 6, max_block: 300, ...}
stigma_shield: {enabled: true, min_level: 1, state_if_below_k: [HIV, MENTAL, MTP, ASSAULT, SEXDET],
               name_threshold_drop: 0.35, selfcheck: stigma, selfcheck_on_fail: auto}
replacements: {relative: "[RELATIVE]", other_name: "[NAME]", unlinked_patient: "[PATIENT]"}
```

The planner works on **patients** (pseudonym clusters), not rows: one level per patient and **one
age band per patient** covering every age seen across that patient's visits (39 and 40 → `35-44` at level 0,
never `20-39` on one row and `40-59` on another), written identically on every row, in text, DOB
cells and FHIR extensions. Bands sit on an aligned grid, with a half-step band (`35-44`, `20-59`)
when the ages straddle an edge. Level 0 releases 10-year bands, sex and district; village, tehsil and
city cells become the record's **own** district (a truthful district-level value, which the scorer
counts as 0.7; `village_to: tehsil` keeps the record's tehsil instead). House/locality/landmark/PIN are
removed. Patients in classes below k on the QIs actually released (band, sex, district; a QI that is
not released matches everyone), and patients with a diagnosis seen in fewer than k patients, move to
level 1 (20-year bands). A rare-diagnosis patient still unique on demographics + diagnosis + stay
length is generalised to the top level as a whole cluster: 40-year band and state only. Such
records stay in the output and are labelled `generalized` in `records.jsonl` (no record is ever
dropped, so `records_suppressed` is 0). Invalid ages (negative, > 120)
become `[AGE]`, never a made-up band. Clinical content is never removed. `report.json` carries
patient-level risk before/after (average, maximum, share below k).

**Trade-off (practice set, `dev_eval/attack_eval.py`, A2 = mean record risk, A4 = share of patients
re-identified at ≥ 0.5 after pooling by pseudonym; raw QI-only attack: A2 0.20, A4 0.73).**

| policy | A2 | A4 | age utility | district utility | medical kept | records at top level (40-y band + state, still exported) |
|---|---:|---:|---:|---:|---:|---:|
| v1 (row-level levels) | 0.060 | 0.21 | 0.57 | 0.69 | 4855 | 78 |
| no suppression | 0.064 | 0.21 | 0.58 | 0.69 | 4855 | 0 |
| **default** (patient-level, rare-dx suppression) | **0.041** | **0.08** | 0.47 | 0.42 | 4851 | 348 |
| `suppress_below_k: true` (strict k = 5) | 0.020 | 0.02 | 0.30 | 0.12 | 4762 | 775 |

The default halves A4 for a small utility cost. Strict k = 5 is one switch away. On 48 patients it
costs district probes and most of the generalisation score, so it is off by default.

### Stigma Shield

`raksha/stigma.py` reads `raksha/data/stigma_terms.txt`: hand-written public clinical and programme
vocabulary in eight categories (HIV, TB, MENTAL, MTP, ASSAULT, LEPROSY, SUBSTANCE, SEXDET), in English,
Devanagari and Hinglish. Short acronyms (`TB`, `ATT`, `MTP`, `ICTC`) must be in capitals; negated mentions
(`HIV 1&2 non-reactive`, `no h/o TB`) do not count. A patient is flagged if any linked record mentions
such a condition. For flagged patients only:

* **Age and place.** At least level 1 (20-year bands). For the categories with a statutory
  confidentiality duty (HIV, mental illness, MTP, sexual assault/POCSO, sex determination), a patient
  still in a class below k at the highest level releases only the state, with a 40-year band. TB and
  leprosy are notifiable diseases and keep the district: public-health use needs it.
* **Facility names.** `ART Centre, Govt Medical College <town>` becomes `ART Centre, [FACILITY]` (also ICTC,
  DOTS, de-addiction/nasha mukti, psychiatry, MTP and leprosy units). The service type, diagnosis text,
  ICD codes, CD4/viral values and regimens stay.
* **Names.** Unseen-name thresholds drop by 0.35 in their files. Relatives are always replaced (as for everyone).
* **Honey-PII self-check** (free-text notes; `selfcheck: all` runs it on every note). Each detected name,
  phone, Aadhaar or ID is swapped in memory for an invented value of the same shape, keyed by
  HMAC(secret, file hash). Names are drawn until they are at least as name-like (to the same scorer) as the
  original, so the check tests the detector's context and not luck. The shadow note goes through the
  same detect + render path. If a planted value survives, the note is re-sanitised in the strictest mode
  and checked again. If a planted number, or more than half the planted names, still survive, the file is
  quarantined (`selfcheck_on_fail: auto`). Nothing planted is written or logged.
  `report.json` → `stigma_shield`: `patients_flagged, records_flagged, records_hardened,
  facility_names_removed, selfcheck_files, selfcheck_planted, selfcheck_caught, files_resanitized_strict,
  files_requarantined`. These are counts only, and `validate_output.py` still says CONTRACT OK.

The self-check paid for itself while it was being built. On invented notes it found three detector gaps,
which are now fixed: a Devanagari name ending in `-डा` was read as the title `डा` (Dr), so the name
leaked; the age/sex bracket frame (`<Name> (54/M), ...`) was missed; and the second name in
`... to <Name> and <Name2>` depended on how name-like the word happened to be. It also exposed a
`District X` parsing slip (`Distt. Rict X`).

### Security

No PII in logs (only counts), in error messages (fixed category strings), in exception traces (custom
excepthook), in `report.json` (no input names or paths; output names are sanitised and carry an HMAC
suffix when renamed), or on disk outside the output folder: nothing is written to TMPDIR or HOME, no
temp files, bytecode writing is disabled. Inputs are opened read-only. Broken, binary, empty, too-deep
or unparseable files are quarantined and never copied.

Release hygiene: the output folder must be empty (or absent), must not be a symlink and must not
overlap the input (checked on resolved paths, both directions); otherwise the run refuses with exit 2
and writes nothing. Everything is built in a private `.release-<pid>` folder inside the output (same
filesystem, never TMPDIR) and moved into place with `os.replace` only after the whole run succeeded;
a failed run removes it and leaves the output empty. Input files are read with `O_NOFOLLOW` and are
re-hashed at the end (a file that changed during the run is reported on stderr as a count). Symlinked
and special files (FIFOs, devices) in the input are never parsed or exported; they are listed in
`report.json` as quarantined (`unsafe_filesystem_entry`). For a symlink to a regular file only the
SHA-256 of its target is computed, because the output contract matches report entries to input hashes.
`report.json` is internally consistent: `identifiers_detected` equals the sum of `entities`, and
`records_processed` equals the lines of `records.jsonl`. Output is identical under any
`PYTHONHASHSEED` (tested without the re-exec in `main.py`, which is kept only as a second guard).
Evaluation scripts live in `dev_eval/` and are never imported by the pipeline (`tests/test_isolation.py`).

## Keep improving it

The name model can be retrained and checked on a laptop with no network and no packages:

```bash
cd <repo>
python3 -m dev_eval.improve                         # one round
python3 -m dev_eval.improve --rounds 10             # ten rounds, new seed each time
python3 -m dev_eval.improve --rounds 5 --kit ../kit # also gate on the kit's practice check_dev
python3 -m dev_eval.improve --extra-words fp.txt    # words it wrongly redacts (one per line) as negatives
python3 -m dev_eval.improve --extra-names nm.txt    # extra INVENTED names as positives (never real patients)
bash dev_eval/demo_stigma.sh && python3 tests/test_stigma.py   # then re-run the checks
```

Each round trains a candidate on the shipped synthetic set plus a fresh one (new seed, slightly varied
hyper-parameters). It then writes a new held-out set of invented notes, with syllable names absent from every
shipped list in English, Hinglish and Devanagari frames, plus person-frame sentences with no name. Both
models run through the full pipeline in a temporary copy of the repo. The candidate replaces
`raksha/namefind_weights.json` only if dev leaks stay 0 and nothing regresses: held-out token F1, name
recall, non-PII retention, synthetic end-to-end leaks/clinical/linkage, and (with `--kit`) practice
medical values and linkage. At least one of them must improve. Every round is appended to
`dev_eval/IMPROVE_LOG.md`, and the loop never trains on real data. So far no candidate has been promoted:
the candidates have higher token F1 but lower name recall at the detector's current thresholds,
so the gate keeps the shipped weights.

## Keep improving it with Gemini

You can ask Gemini 4 Neon to *write tricky test records*, and let Raksha learn from them. Gemini is only
used by you, in your browser, to make a text file. Raksha never calls Gemini or the internet, so the
hackathon "no AI model, offline" rule still holds.

1. Open `dev_eval/GEMINI_PROMPT.md`, copy the prompt inside the box, and paste it into Gemini.
2. Save Gemini's whole answer as `cases.jsonl` in the repo folder. Each line is one invented record:
   the text, the personal data in it (`pii`), and the medical words that must stay (`must_keep`).
   `dev_eval/gemini_cases_example.jsonl` shows what a good file looks like.
3. See how Raksha does on them today:
   ```bash
   python3 -m dev_eval.gemini_cases cases.jsonl          # only checks the file
   python3 -m dev_eval.gemini_cases cases.jsonl --run    # also runs Raksha and lists every leak
   ```
   Broken lines (not JSON, a `pii` text that is not really in the record, an unknown type, ...) are
   skipped with the line number and the reason; the rest still runs. Fix or delete them if you like.
4. Let the improve loop learn from them:
   ```bash
   python3 -m dev_eval.improve --rounds 5 --kit ../kit --gemini-cases cases.jsonl
   ```
   The cases are split in two halves (always the same split for the same file). The names in one half
   become extra training words for the name model; the other half is kept aside as a test it has
   never seen. The new model replaces the old one only if practice leaks stay 0 and nothing gets worse,
   including leaks and kept medical values on that held-out half.
5. Run the tests again (`python3 tests/test_namefind.py` etc.) and commit if something was promoted.

What it can and cannot fix: retraining only teaches the *name* model. If `--run` shows a leaked phone,
ID, date or address, that is a missing rule in `raksha/detect.py`; add a general rule (never the exact
value), add an invented example to `tests/test_structural.py`, and check the practice set still has
0 leaks. Never put real patient data in the cases file.

## Known limitations

* A given name never seen in a structured field, with no surname/suffix, Hinglish, honorific or role
  cue next to it, and absent from the gazetteer can still slip through in free text; on our sealed
  synthetic notes 12–16% of invented names are still missed (weakest: cue-less Devanagari with a
  singular verb). Cue-less person frames (`X aaye`, `X बोले`, `spoke to X`) also catch unknown group or
  role nouns and English unit names in the same slot (`मेहमान आए`, `Spoke to Mortuary`), costing about
  1.5–5% of tokens in adversarial notes built from such sentences.
* Free-text addresses without a trigger word are found by structure (house number + locality head such as
  `Nagar/Tola/Colony/नगर/टोला`, landmarks such as `near X Mandir`, `X मंदिर के पास`, PIN after a place);
  a locality without a head word or landmark is still missed.
* Linkage is deliberately conservative: first-name-only fragments without phone/ID/relative stay unlinked.
* Homonym guard: a record whose only link evidence is name/age/place and that fits two clusters already
  proven to be different people (a veto between them, e.g. same name but different father) stays unlinked.
* Date side channels: dates in file names move with the file's own shift, and weekday names on a line
  with a shifted date become `[DAY]` (they would reveal the true weekday). Festival names ("Holi",
  "Diwali") with a year, or in a time frame ("since Holi", "Diwali ke baad"), become `[DATE]` / `[EVENT]`;
  fixed-date days with a year ("Republic Day 2025") are shifted like any date. A bare festival name
  with no time frame is kept as clinical context.
* k-anonymity is computed within the release. With the default policy, k = 5 is not met for every
  patient (75% of the 48 practice patients sit in classes below 5 on band/sex/district); the registry
  attacker numbers above are the honest measure. `suppress_below_k: true` enforces it.
* `report.json` timing and peak RSS differ between runs (required fields). Everything else, and every
  sanitized file and records.jsonl, is byte-identical for the same input and secret.
* Stigma Shield: the honey self-check covers free-text notes. CSV/JSON/FHIR fields are typed by column
  and key and are not self-checked. Facility names are removed from free text and JSON/FHIR strings,
  but not from CSV cells. A patient whose stigmatised condition is described only in words outside the
  vocabulary (for example a euphemism) is not flagged.
* Ages written in words are found in an age frame (age cue, unit + ka/ki/old, `वर्षीय`, brackets).
  A number-word spelling missing from the built-in English/Hindi/Hinglish list ("chausath") is missed.
  So is a spelled age written as a duration ("for sixty years").
* Formats beyond CSV/TSV/JSON/FHIR/HL7v2/text (NDJSON/JSON Lines, PDF, images, XML) are quarantined.
* Quarantine policy (v1.9): files with invalid bytes, JSON with NaN/Infinity or duplicate keys, and JSON
  saved under a .csv name are quarantined. The official spec accepts either quarantine or a safe export
  for such files; the Opus kit requires quarantine, so we quarantine (valid under both). On the practice
  set this moves `corrupt_bytes_note.txt` and `mislabeled_export.csv` from exported to quarantined.
* Phones with mixed separators (`98.11-20 44`) or slashes are missed; an unknown first-name + surname
  pair in free text with no cue, no Title Case pair and no gazetteer hit can still slip through.

## Design notes and credits

Built during the event. The two-pass design, clinical shielding, Verhoeff booster, IDF-weighted names,
phone-degree cap, veto-aware clustering, residual sweep, HKDF domain separation and cluster-anchored
pseudonyms follow our design review; CRF taggers, large census gazetteers and heavy anonymisation
libraries were rejected (no time, memorisation risk, or unnecessary weight). No development data,
names or answers are embedded in the code; gazetteers are generic hand-made lists.
